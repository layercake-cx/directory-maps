Pattern · archive and restore

Archive, never delete

Directories, maps and customers can be archived. Archiving takes the thing offline and out of everyday lists, keeps every record, and is undone with Restore. Because it takes live sites down, it asks you to type ARCHIVE first.

Nothing is deleted. Restore it from Archived at any time and it comes back as it was.

ArchiveSets archived (is_active false, archived_at, archived_by). Keeps every row, publication, file and setting. Takes the item offline. Pauses its scheduled syncs and AI jobs. Never deletes.
RestoreClears the archive fields. The item comes back exactly as it was: live again if it was published, draft if it wasn't. Paused schedules resume. Restoring a customer restores access but not items that were archived separately before.
Who canDirectories and maps: managers of the organisation and staff. Customers: Layercake staff only. View-only users see archived items read-only and no archive controls.
